### Feature matrix — Python's AAD leaves out a prefixing backend's key prefix

- The **AAD v0x03 (cache_key binding)** row no longer marks Python ✅. Through `cachekit`
  0.22.0 the AAD `cache_key` is the call key alone, so a prefixing backend's key prefix
  (`MemcachedBackend` `key_prefix`, the tenant-scoped Redis backend's `t:{tenant}:`) is not
  bound, short of the [logical backend key](spec/encryption.md#additional-authenticated-data-aad)
  definition. The fix is [cachekit-py#518](https://github.com/cachekit-io/cachekit-py/pull/518),
  unreleased; the cell gets a version floor once a release carries it.
- The **Compliance Status** table's AAD v0x03 cell for Python carries the same exception, so
  the file no longer marks Python fully compliant there while the Encryption table says it is
  not.
