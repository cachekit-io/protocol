### SDK feature matrix and intent presets — Python cells brought to the published cachekit 0.20.0 (LAB-6902)

- Every flip below was verified against the published `cachekit` 0.20.0 wheel (PyPI,
  2026-10-03), not the repository branch. Rust and TypeScript cells are unchanged.
- **Default TTLs.** Python presets default to 300 / 600 / 600 / 3 600 s from 0.20.0, and
  `CACHEKIT_DEFAULT_TTL` is gone. Both [intent-presets](spec/intent-presets.md#sdk-conformance)
  TTL rows are ✅ for Python, and the [matrix](sdk-feature-matrix.md#intent-preset-semantics-parity-not-presence)
  TTL cell and its warning no longer say Python entries never expire.
- **`secure` holds only ciphertext in L1.** From 0.20.0, `@cache.secure(backend=None)` and
  any other encrypting decorator with `backend=None` raise `ConfigurationError` at
  decoration. The "`secure`: L1 on, ciphertext only" and "explicit encryption option
  encrypts every operation" rows are ✅ for Python.
- **`io` credentials.** `@cache.io` takes `api_key=` or falls back to `CACHEKIT_API_KEY`,
  and rejects `backend=` from 0.20.0. The conformance row and the matrix credentials cell
  are ✅; [Explicit Configuration](spec/intent-presets.md#explicit-configuration) rule 2 no
  longer records a non-conformance.
- **Default `tenant_id`.** The row stays ✅ and gains the 0.20.0+ floor: 0.19.0 does not
  carry it.
- **Client-L1 stale-while-revalidate** stays ⚠️ for Python: L1-only mode only. From 0.20.0
  the `production` and `dev` presets get it without `ttl=`; a bare `@cache(backend=None)`
  still needs one. [Matrix](sdk-feature-matrix.md#reliability-features) note ¹⁰ says so.
