### Cache-key format — the `func:` segment is a Python module path only (LAB-7475)

- The Cross-SDK limitation callout in
  [`spec/cache-key-format.md` → Key Format](spec/cache-key-format.md#key-format) no longer
  describes the `func:` segment as a "Rust crate path" or "Go package path", and names the
  format as cachekit-py's. There is no Go SDK, and cachekit-rs has no auto-mode key format.
- [`spec/interop-mode.md` → The Problem](spec/interop-mode.md#the-problem) drops its Go
  auto-mode key example for the same reason.
- [`spec/interop-mode.md` → Two Modes](spec/interop-mode.md#two-modes): the auto-mode
  `Key format` and `Operation identity` cells now give each SDK's shape (Python's
  7-segment key, TypeScript's `{namespace}:{hash}`, none for Rust) instead of presenting
  Python's as every SDK's.
- The Full Key Structure note and the
  [Server-Side Requirements](spec/cache-key-format.md#server-side-requirements)
  `Default namespace` row now say "Rust caller-supplied keys" where they said Rust keys
  were `{ns}:{hash}`: cachekit-rs prefixes the caller's key and hashes nothing.
- [`spec/interop-mode.md` → Design Decisions](spec/interop-mode.md#design-decisions) no
  longer says cachekit-rs has no in-SDK keygen: its only one is interop mode.
- Clarification only: no key byte, segment or derivation step changed.
