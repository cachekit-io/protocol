### Interop v2 — testable body decode bounds, catchable rejection, count and truncation vectors (LAB-7536)

- [`spec/interop-v2.md` → SDK Implementation Requirements](spec/interop-v2.md#sdk-implementation-requirements),
  item 7: the conformance test drives each reject vector through every interop/v2 read
  entry point and, for vectors rejected at steps 2 to 4, asserts an error from a check
  made before any allocation sized from the body, as `wire-format.md` and
  `interop-mode.md` (IOP-31) already require. An implementation that supports a 32-bit
  target runs every reject vector there too.
- [Every v2 rejection MUST be catchable](spec/interop-v2.md#catchable-rejection): never a
  panic, an uncaught crash or an out-of-memory abort.
- The remaining-bytes check MUST use arithmetic that cannot wrap (for example
  `n > len − pos`). Reader Algorithm step 2 rejects a container shorter than 2 bytes.
- `test-vectors/interop-v2.json` 1.4.0 adds eleven reject vectors: three body counts other
  than 3 with a complete value (`reject_count_*`), `reject_forged_bin32_length_within_caps`,
  two containers shorter than 2 bytes (`reject_container_*`), and five truncated bodies
  (`reject_truncated_*`). The reference self-check gains a count-blind reader.
- interop/v2 is a draft that no SDK implements, so no conformance cell changes.
