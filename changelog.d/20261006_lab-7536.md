### Interop v2 — testable body decode bounds, catchable rejection, count and truncation vectors (LAB-7536)

- [`spec/interop-v2.md` → SDK Implementation Requirements](spec/interop-v2.md#sdk-implementation-requirements),
  item 7, now requires the conformance test to drive each reject vector through the
  interop/v2 read entry point and, for vectors rejected at steps 2 to 4, assert an error
  that only a check made before allocation produces. This brings `wire-format.md`'s
  envelope duty and `interop-mode.md`'s IOP-31 to the v2 body: a reader that allocates
  4 GiB from a forged `bin32` length and then runs out of input also errors, so a verdict
  alone cannot show the declared-length budget holds.
- [Every v2 rejection MUST be catchable](spec/interop-v2.md#catchable-rejection): never a
  panic, an uncaught crash or an out-of-memory abort. It is Decode bounds rule 3 without
  the cache-miss mapping.
- The remaining-bytes check MUST compare a declared length with the bytes that remain
  (`len − pos`), since `pos + n` wraps in a 32-bit type. Reader Algorithm step 2 rejects
  a container shorter than 2 bytes. `#check-order` now reads "the body has passed the
  declared-length budget (Decode bounds rule 2)".
- `test-vectors/interop-v2.json` 1.4.0 adds seven reject vectors: three body counts other
  than 3 with complete elements (`reject_count_array16_forged`,
  `reject_count_array32_forged`, `reject_count_four`), which a reader that skips the count
  check accepts, and four truncated bodies (`reject_truncated_*`). The reference
  self-check gains a count-blind reader that must accept exactly the three count vectors.
  `reject_forged_bin32_length`'s description now names the declared-length budget and the
  remaining-bytes check instead of a retired rule name.
- interop/v2 is a draft that no SDK implements, so no conformance cell changes.
