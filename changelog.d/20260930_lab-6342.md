### Wire format — a ByteStorage vector that fails a 32-bit ratio product (LAB-6342)

- [`test-vectors/wire-format.json`](test-vectors/wire-format.json) **1.2.0** adds
  a `constructed_vectors` group with one vector,
  `envelope_ratio_product_wraps_32_bits`: a canonical `bin` envelope whose
  `compressed_data` is 4,294,968 B, with an `original_size` of 8,523,079 B, which
  readers MUST accept. A reader that computes the ratio product in 32 bits, signed
  or unsigned, gets a bound of 704 B and rejects it. The original is larger than the
  compressed data, so a reader that skips the product when the original is no larger
  still has to compute it. Until now the largest envelope in the file was 478 B,
  and such a reader passed every vector. The envelope is
  described as repeated byte segments, the same form as `interop-v2.json`. The 14
  hex-pinned vectors are unchanged.
- [`spec/wire-format.md` → Decompression Bomb Detection](spec/wire-format.md#decompression-bomb-detection)
  gains a MUST: an implementation of the ByteStorage envelope that supports a 32-bit
  target (such as `wasm32`, defined in interop-v2.md item 7) passes the vector on
  each such target. The read-side conformance bullet now says what the vector does
  and does not show.
- [`tools/wire-format-reference.py`](tools/wire-format-reference.py) gains a reader,
  `read_envelope`, that runs the Retrieve Flow with every size and ratio bound (the
  step-2 decode-bounds pre-scan is `decode-bounds.json`'s subject). It
  reuses the pure-Python LZ4 decoder from `tools/interop-v2-reference.py`. With the
  optional `xxhash` package it verifies every vector's checksum, pinned and
  constructed. CI's optional-deps leg now installs `xxhash==4.0.1` and requires it.
- **New CI guard**:
  [`tools/test_wire_format_reference.py`](tools/test_wire_format_reference.py)
  swaps the reader's ratio check for four 32-bit versions (unsigned wrap, signed
  wrap, reject on overflow, and unsigned wrap behind an original-no-larger fast
  path). Each passes every hex-pinned vector and fails the new one. It also calls the
  reader's reject branches directly (flipped checksum, envelope cap, size cap, empty
  `compressed_data`), so deleting any of them fails CI. `verify` fails if the
  constructed vector is dropped or altered, and, on the `xxhash` leg, if its
  checksum is wrong.
- **For SDKs that vendor `wire-format.json`:** re-vendoring 1.2.0 changes the file's
  sha256. Loaders that read only `vectors` keep passing; running the new vector
  means building it from its segment lists.
