### Conformance — requirement ids, a requirement-to-vector index and per-SDK coverage

- **Requirement ids** ([conformance/README.md](conformance/README.md)): every MUST and
  MUST NOT in [interop-mode.md](spec/interop-mode.md) now carries an id, `IOP-1` to
  `IOP-36`, written beside its keyword as a superscript and linkable as
  `spec/interop-mode.md#iop-<n>`. No normative text changed; `tools/conformance.py strip`
  removes the ids so the diff can be checked.
- **Index** ([conformance/requirements.json](conformance/requirements.json)): maps each id
  to the vectors and reference-tool tests that exercise it, and records what no vector
  reaches as a gap. Of the 36 interop-mode requirements, 17 are fully pinned by vectors,
  11 partly, 3 only by reference-tool self-tests, and 5 by nothing.
- **Per-SDK coverage** ([conformance/coverage.md](conformance/coverage.md)): generated
  from the index and [conformance/sdks.json](conformance/sdks.json), which records the
  sha256 of every fixture copy each SDK vendors. Each copy is matched to a revision of the
  fixture here, so a requirement counts as covered only when the SDK's copy holds every
  mapped vector exactly as published.
- **Check** (`tools/conformance.py check`, with a mutation suite run first): fails when a
  MUST in an indexed file has no id, an id is missing from the index, the index names a
  vector or test that does not exist, an id is dropped instead of retired, or the report is
  stale. No fixture changed.
