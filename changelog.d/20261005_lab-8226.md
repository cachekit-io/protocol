### Test vectors — master key input rows in encryption.json (LAB-8226)

- [`test-vectors/encryption.json`](test-vectors/encryption.json) `1.3.0` adds a `master_key_input`
  block for [intent-presets.md → Master Key Input](spec/intent-presets.md#master-key-input). Every
  row comes from one key, under the tenant `"default"`.
  - **One accept row.** Its key has a leading zero byte, 14 bytes above `7f`, and every hex digit in
    both places of a byte. The row carries its derived-key fingerprint and a sealed interop entry, so
    a test can read it through a `secure` preset given no tenant. The entry is `interop-mode.json`'s
    `empty_args` key holding its `mixed_array` value, so it shares neither key nor value with
    `default_tenant_interop`.
  - **Eleven hex rejects:** 65 digits, 63 digits, a last digit that is not hex, 64 digits followed by
    `gg`, a leading `+`, 31, 24 and 16 bytes, and 31 bytes with CR LF after them, with spaces between
    pairs, or with `0x` before them.
  - **Five raw-key rejects:** 16, 24, 31 and 33 bytes, and the 64 ASCII bytes of a hex string.

  No existing vector changed. No row's verdict turns on an uppercase letter, white space or a `0x`
  prefix, which rule 1 does not settle. Every row also gets the same verdict whether an SDK takes
  exactly 32 bytes or 32 and more.
- [`tools/encryption-verify.py`](tools/encryption-verify.py) verifies the rows. It models each mistake
  a row's note names as a wrong entry point that must misjudge that row. It refuses any vector table
  it does not verify, a duplicate row name, and an accept row that shares its master key, cache key
  or plaintext with a `default_tenant` entry.
  [`tools/test_encryption_verify.py`](tools/test_encryption_verify.py) adds a mutation case for each
  guard, each naming the failure text of the guard it targets.
- [`spec/intent-presets.md`](spec/intent-presets.md#design-decisions): the design decision "No test
  vectors", now titled "Vectors only for the key bytes", says that Master Key Input's rules 1, 3, 4
  and 5 have vectors, that its rule 2 and the rest of the specification have no fixture of their own,
  and why. No normative text changed.
- [`conformance/coverage.md`](conformance/coverage.md):
  - PRE-16 to PRE-18, PRE-22, PRE-23, PRE-26 and PRE-51 list the new rows and have narrower gaps.
    PRE-23 moves from gap only to vectors and a gap.
  - PRE-25, PRE-28 and ENC-6 name their sealed vectors instead of the whole file, and ENC-1's gap now
    speaks of every sealed vector. PRE-52's gap drops a clause the new rows make false.
  - PRE-20, PRE-21, PRE-33, PRE-45, PRE-46 and PRE-49 now name the construction case no vector holds,
    since the reject rows are refused at construction in some SDKs.
