### Test vectors — master key input rows in encryption.json (LAB-8226)

- [`test-vectors/encryption.json`](test-vectors/encryption.json) `1.3.0` adds a `master_key_input`
  block for [intent-presets.md → Master Key Input](spec/intent-presets.md#master-key-input). Every
  row comes from the key `000102…1f`, under the tenant `"default"`. One accept row (32 distinct
  bytes, a leading zero byte, lowercase hex letters) carries its derived-key fingerprint and a
  sealed interop entry, so a test can read it through a `secure` preset that is given no tenant.
  Six hex rejects: 65 and 63 digits, a last digit that is not hex, 64 digits followed by `gg`, 31
  bytes and 16 bytes. Three raw-key rejects: 31 and 33 bytes, and the 64 ASCII bytes of a hex
  string. No existing vector changed. No row holds an uppercase letter, white space or a `0x`
  prefix, which rule 1 does not settle, and every row gets the same verdict whether an SDK takes
  exactly 32 bytes or 32 and more.
- [`tools/encryption-verify.py`](tools/encryption-verify.py) verifies the rows. It models each
  mistake a row's note names as a wrong entry point that must misjudge that row: a big-integer
  decoder that drops a leading zero byte, Node's `Buffer.from` ahead of a length check, an
  off-by-one or AES-key-size length rule, a raw-bytes path that takes 32 bytes or more, and
  others. It also refuses a vector table it does not verify.
  [`tools/test_encryption_verify.py`](tools/test_encryption_verify.py) adds a mutation case for
  each guard.
- [`spec/intent-presets.md`](spec/intent-presets.md#design-decisions): the "No test vectors"
  design decision now says that Master Key Input's byte-level rules have vectors and that the
  rest of the specification has none, and gives the reason. No normative text changed.
- [`conformance/coverage.md`](conformance/coverage.md): PRE-16 to PRE-18, PRE-22, PRE-23, PRE-26
  and PRE-51 list the new rows and have narrower gaps. PRE-23 moves from gap only to vectors and a
  gap. PRE-25, PRE-28 and ENC-6 name their sealed vectors instead of the whole file.
