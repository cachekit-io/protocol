### Interop v2 — container body decoded under Decode bounds rules 1 and 2 (LAB-7219)

- [`spec/interop-v2.md` → The v2 Value Container](spec/interop-v2.md#the-v2-value-container)
  now decodes the body under the depth and allocation rules of
  [`interop-mode.md` → Decode bounds](spec/interop-mode.md#decode-bounds), as
  `wire-format.md` already does for the envelope. Every `bin`, `str` and `ext` length and
  every `array` and `map` count in the body counts toward the declared-length budget. The
  old rule covered only `bin` length headers, so a reader could allocate from the
  `array32` count in the 7-byte container `c1 02 dd ff ff ff ff` and still conform. The
  old `bin`-only length check becomes the remaining-bytes check, a MUST beside the budget:
  a reader checks that the body holds every byte before it reads it (markers, length and
  value fields, `ext` type bytes, and `bin`, `str` and `ext` data), and checks data before
  it allocates for it.
- Decode bounds rule 3's cache-miss mapping does not apply, so a rejected body stays a hard
  error.
- The SDK checklist's read-side reject list now includes a truncated body and a body over
  the depth bound or the declared-length budget.
- No vector changed. interop/v2 is a draft that no SDK implements, so no conformance cell
  changes.
