### Interop v2 — the container body is decoded under the decode-bounds allocation rules (LAB-7219)

- [`spec/interop-v2.md` → The v2 Value Container](spec/interop-v2.md#the-v2-value-container)
  now decodes the body under the depth and allocation rules of
  [`interop-mode.md` → Decode bounds](spec/interop-mode.md#decode-bounds), as
  `wire-format.md` already does for the envelope. Every `bin`, `str` and `ext` length and
  every `array` and `map` count in the body counts toward the declared-length budget. The
  old rule covered only `bin` length headers, so a reader could allocate from the
  `array32` count in the 7-byte container `c1 02 dd ff ff ff ff` and still conform.
- A hand-written parser of the three-field grammar needs no separate walk if it reads every
  element itself, never through a generic MessagePack decoder, and, before it decodes into
  an element or allocates anything sized from a header it has read, rejects a first header
  that is not an `array` of count 3, a marker at `[0]` or `[1]` that is not an
  unsigned-family int, a marker at `[2]` that is not `bin`, and a `bin` length past the end
  of the input.
- A rejected body is a hard error, not a cache miss.
- The SDK checklist's read-side reject list now includes a body over the budget.
- No vector changed. interop/v2 is a draft that no SDK implements, so no conformance cell
  changes.
