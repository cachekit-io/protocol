### Reference tools — the stdlib LZ4 block decoder accepts only `00` for a 0-byte output (LAB-6918)

- `lz4_block_decompress` in `tools/interop-v2-reference.py`, shared by the
  `interop-v2`, `python-frame` and `wire-format` verifiers, now rejects any block other
  than the single byte `00` when `original_size` is 0. Before, it also accepted the
  one-byte blocks `01` to `0f`, which declare no literals and so never reached their
  match-length nibble.
- This matches liblz4. Measured with python `lz4` 4.4.5 (liblz4 1.9.4),
  `lz4.block.decompress(block, uncompressed_size=0)` accepts `00` and rejects each of
  `01` to `0f`.
- No committed vector changes: the only block decoded at `original_size` 0 is
  wire-format's `empty` vector, whose block is `00`. Behaviour at every other
  `original_size` is unchanged. The JavaScript LZ4 decoders in the cross-check tools
  are unchanged.
