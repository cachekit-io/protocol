### SaaS API — `503` covers transient storage faults on every cache operation (LAB-6168)

- [`spec/saas-api.md` → Error Handling](spec/saas-api.md#error-handling): the `503` row
  now says the server answers a transient storage fault with `503` and `Retry-After`,
  on reads and writes alike, and keeps `500` for a genuine backend failure. Before, the
  row named only overload and auth-source faults. SDKs are unaffected: `500` and `503`
  are both in the Transient class.
