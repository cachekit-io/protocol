### Reference tools — the stdlib LZ4 block decoder enforces LZ4's end-of-block rules (LAB-6886)

- `lz4_block_decompress` in `tools/interop-v2-reference.py`, shared by the
  `interop-v2`, `python-frame` and `wire-format` verifiers, now enforces the two LZ4
  block-format end-of-block rules. It rejects a block whose last match starts within
  12 bytes of the end, as liblz4 does when it decodes into an `original_size` buffer.
  It also rejects a block whose last match reaches into the last 5 bytes. That check
  is stricter than liblz4, which skips it on its fast path and accepts some of those
  blocks. Before, this decoder accepted both kinds of block.
- No committed vector changes: every published block already follows both rules.
  `tools/test_interop_v2_reference.py` pins one rejecting block per rule, and a short
  literals-only block that must still decode.
- The JavaScript LZ4 decoders in the cross-check tools are unchanged and still accept
  both kinds of block.
