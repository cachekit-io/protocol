### Conformance — MUST and NOT split by a line break that GitHub may show

- **Split MUST NOT** (`tools/conformance.py`): MUST and NOT on two lines of an HTML block, or
  across a hard line break (two spaces or a backslash at the end of a line), are an error
  wherever the id sits. A `<pre>` element keeps a line break and a `<div>` does not, and the
  checker tracks no elements, so an id after NOT could mark a MUST shown alone on its line, and
  an id after MUST could show between the two words. Before, the first read as a MUST with no
  id and a stray id, and the second passed. Keep MUST NOT on one line there.
- **Inline `<pre>`**: a raw `<pre>` tag inside a paragraph, heading or table cell is an error.
  GitHub closes the paragraph before the element and keeps the line breaks inside it, so the
  checker read MUST and NOT on two of its lines as one phrase that GitHub shows on two lines.
  Start the element on a line of its own. No spec file's keywords change; see
  [conformance/README.md](conformance/README.md).
