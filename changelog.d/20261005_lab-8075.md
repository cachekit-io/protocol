### Feature matrix — the reject vectors and every vendored fixture the SDKs' CI runs

- The **Wire format** row and note ¹⁶ no longer say no SDK runs the six `wire-format.json`
  1.3.0 [reject vectors](spec/wire-format.md#reject-vectors). cachekit-py runs all six through
  `ByteStorage.retrieve` since 0.21.0
  ([cachekit-py#448](https://github.com/cachekit-io/cachekit-py/pull/448)); cachekit-ts runs
  them on `main` in its Node and Workers lanes
  ([cachekit-ts#198](https://github.com/cachekit-io/cachekit-ts/pull/198)), unreleased. The
  allocation-bound caveat stays on both cells: no `cachekit-core` release has the probe.
  Note ¹ no longer says the reject vectors do not run in the cachekit-ts Workers lane.
- The **Test vectors in CI** row now lists every fixture each SDK vendors and runs, with its
  version: cachekit-py `cache-keys.json` 1.1.0, `file-backend.json` 1.1.0 and
  `wire-format.json` 1.3.0 (since 0.21.0); cachekit-rs `file-backend.json` 1.1.0 (since 0.9.0);
  cachekit-ts `wire-format.json` 1.3.0 (unreleased) and `encryption.json`, whose vendored copy
  is 1.1.0 against this repo's 1.2.0 (since 0.1.4). Note ¹⁶ dates cachekit-py's
  `cache-keys.json` 1.1.0 to 0.21.0.
