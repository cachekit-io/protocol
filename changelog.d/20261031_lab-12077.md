### SaaS API — L1 hit-latency telemetry and the telemetry switch

- [`spec/saas-api.md` § L1 hit latency](spec/saas-api.md#l1-hit-latency) (new) defines two
  optional headers that report how long calls served from L1 take, as the caller sees them:
  `X-CacheKit-L1-Latency-Buckets` (sixteen fixed buckets doubling from 128 ns to about
  2.1 ms, the last one open; their sum is the number of hits timed) and
  `X-CacheKit-L1-Latency-Sum-Ns`. Values are counted per report, not per session, kept per
  CachekitIO backend instance, taken atomically and sent on exactly one attempt. An SDK may
  time a random sample of calls, and sends no latency headers from a runtime whose clock
  cannot resolve an L1 hit, such as Cloudflare Workers
  ([API-79](spec/saas-api.md#api-79)–[API-87](spec/saas-api.md#api-87)).
- [`spec/saas-api.md` § Telemetry switch](spec/saas-api.md#telemetry-switch) (new): every SDK
  exposes an optional `telemetry` setting and reads `CACHEKIT_TELEMETRY`; either one turned off
  stops every optional metrics header. `X-CacheKit-L1-Status` is still sent. Default: on
  ([API-91](spec/saas-api.md#api-91), [API-92](spec/saas-api.md#api-92)).
- [`spec/saas-api.md` § Optional Metrics Headers](spec/saas-api.md#optional-metrics-headers):
  the headers are client-reported observability, sent only to the configured CachekitIO API
  ([API-77](spec/saas-api.md#api-77)). The server never reads them for billing or rate
  limiting and never rejects a request over one, and a bad latency set never drops the session
  headers, or the reverse ([API-88](spec/saas-api.md#api-88)–[API-90](spec/saas-api.md#api-90)).
- [`spec/saas-api.md` § L1 hit rate](spec/saas-api.md#l1-hit-rate) (new) pins
  `X-CacheKit-L1-Hit-Rate` to `L1-Hits / (L1-Hits + L2-Hits + Misses)`
  ([API-78](spec/saas-api.md#api-78)). **Changes cachekit-py**, which sends
  `L1-Hits / (L1-Hits + L2-Hits)`.
- [`sdk-feature-matrix.md` § Observability](sdk-feature-matrix.md#observability): rows for the
  latency headers and the telemetry switch, unshipped in every SDK, and the Python hit-rate
  difference on the telemetry-headers row.
