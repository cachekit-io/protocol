### Interop v2 — decode bounds run before any output allocation (LAB-6782)

- [`spec/interop-v2.md` → Reader Algorithm](spec/interop-v2.md#check-order) now orders
  the decode bounds before output allocation as well as before decompression, matching
  [`wire-format.md`](spec/wire-format.md#check-order). The old text required only that
  bounds run before decompression, so a reader could reserve an output buffer sized from
  `original_size` or the payload length before its checks and still conform.
- Rejecting an unregistered `method` is now the first Security Limits check, so it too
  runs before any output allocation.
- The SDK Implementation Requirements checklist and the reject-vector table now follow the
  same order: Security Limits vectors error at or before step 4. The `security_limits`
  note in [`test-vectors/interop-v2.json`](test-vectors/interop-v2.json) links the rule;
  no vector changed.
- interop/v2 is a draft that no SDK implements, so no conformance cell changes.
