### Wire format — a CK v3 frame header may carry trailing spaces that align the payload (LAB-9999)

- [Python: CK v3 frame](spec/wire-format.md#python-ck-v3-frame): a writer MAY follow the
  HEADER's JSON object with ASCII spaces, counted in `HDR_LEN`, to align the payload.
  `cachekit-py` does so for uncompressed, unencrypted Arrow payloads, so the Arrow IPC file
  starts on a 64-byte boundary of a File backend cache file.
- `test-vectors/python-frame.json` gains `padded_header_frame`: `raw_payload_frame` with its
  header padded so the payload starts at frame offset 128. Both reference readers parse it to the
  same header and payload. It is parse-level only: an SDK test that re-wraps each vector's header
  and payload and compares bytes must skip it, since re-wrapping without padding gives other bytes.
- Not breaking: JSON allows trailing whitespace, so a reader parses a padded header unchanged.
  Unpadded frames stay valid, and every existing vector is unchanged.
