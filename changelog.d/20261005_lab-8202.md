### Test vectors — path-encoding rows for encoder mistakes, and the freshness headers

- [`test-vectors/path-encoding.json`](test-vectors/path-encoding.json) `1.2.0` adds twelve
  transmittable rows: a backslash (a WHATWG URL parser reads a raw `\` as `/`), a tab, CR and
  LF (which the parser strips, so a raw `.<TAB>.` arrives as `..`), the other control
  characters, existing percent-escapes (`%2e%2e`, which an encoder that keeps escapes raw sends
  as a dot segment, and `User%3AKey`, which it sends as the key `User:Key`), two- and four-byte
  UTF-8, `-` and `~`, uppercase letters, and the ASCII delimiters no row held. No existing row
  changed, and the Python, TypeScript and Rust reference encoders produce every new row's
  `encoded` form.
- New [`test-vectors/freshness-headers.json`](test-vectors/freshness-headers.json) `1.0.0`
  pins how an SDK reads `X-CacheKit-Freshness` and `X-CacheKit-Fresh-For` on a `GET` `200`, as
  field value → result rows, CI-verified by
  [`tools/freshness-headers-verify.py`](tools/freshness-headers-verify.py) (stdlib; a mutation
  self-test runs first, and each wrong reader a row's note names must misread a row).
  [`spec/saas-api.md`](spec/saas-api.md#get-v1cachekey) points to it beside the response
  headers; no normative text changed.
- [`conformance/coverage.md`](conformance/coverage.md): `API-4` to `API-7` and `API-17` list
  the new path rows, and `API-18`, `API-33` and `API-34` the header rows. Each keeps the gap no
  vector closes: the rows reach an SDK's encoder or header parser, not the request it builds or
  the response it reads. The report shows a vector name that is not all printable as its JSON
  string literal.
