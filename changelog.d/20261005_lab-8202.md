### Test vectors — path-encoding rows for encoder mistakes, and the freshness headers

- [`test-vectors/path-encoding.json`](test-vectors/path-encoding.json) `1.2.0` adds fifteen
  transmittable rows: a backslash (a WHATWG URL parser reads a raw `\` as `/`), a tab, CR and
  LF (which the parser strips, so a raw `.<TAB>.` arrives as `..`), a space or C0 control at the
  end of the key (which the parser strips from the end of the URL, so a raw `.. ` reaches
  `/v1/`), the control characters at the ends of their ranges (NUL, 0x1F, DEL), existing
  percent-escapes (`%2e%2e`, which an encoder that keeps escapes raw sends as a dot segment, and
  `User%3AKey`, which it sends as the key `User:Key`), two-, three- and four-byte UTF-8 (the
  three-byte `‥` normalises to `..` under NFKC), `-` and `~`, uppercase letters, and the ASCII
  delimiters no row held. No existing row changed. CI checks every row against Python's
  `quote(key, safe="")` and its `encodeURIComponent` form.
- New [`test-vectors/freshness-headers.json`](test-vectors/freshness-headers.json) `1.0.0`
  pins how an SDK reads `X-CacheKit-Freshness` (9 rows) and `X-CacheKit-Fresh-For` (22 rows)
  on a `GET` `200`, as field value → result rows. Each row's note names the parser mistakes it
  catches: a case-insensitive, prefix or list-item label match, or a label trimmed of a
  no-break space; a sign, a decimal point, an exponent, a hex prefix or an underscore; white
  space inside the value or trimmed from it; a missing length check (eight digits, and values
  that wrap a 32- or 64-bit integer or exceed CPython's 4,300-digit `int()` limit); non-ASCII
  digits; and 0 read as no value. CI verifies the rows with
  [`tools/freshness-headers-verify.py`](tools/freshness-headers-verify.py) (stdlib), which then
  runs a self-test: each poisoned copy of the fixture must trip the guard it names, and each
  reader in its table of wrong readers must misread the rows it lists.
  [`spec/saas-api.md`](spec/saas-api.md#get-v1cachekey) points to the fixture beside the
  response headers; no normative text changed.
- [`conformance/coverage.md`](conformance/coverage.md): `API-4` to `API-7` and `API-17` list
  the new path rows, and `API-18`, `API-30`, `API-33`, `API-34` and `API-57` list header rows.
  Each keeps the gap no vector closes: the rows reach an SDK's encoder or header parser, not
  the request it builds or the response it reads. The report shows a vector name as its JSON
  string literal when the name is not all printable or could pass for another.
