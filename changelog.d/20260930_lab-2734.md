### Decompression bomb bound — `original_size` is compared at its full wire value (LAB-2734)

- [`spec/wire-format.md`](spec/wire-format.md) § Security Limits and
  [`spec/interop-v2.md`](spec/interop-v2.md) § Security Limits now require the
  `MAX_UNCOMPRESSED` comparison to be decided on the **full wire value** of
  `original_size`. A reader decodes it into a ≥ 64-bit unsigned or
  arbitrary-precision integer or a binary64, or rejects a value that does not fit
  a narrower type that still holds every legal size (such as `u32`). Any decode
  that does not yield the exact wire value is forbidden: truncation to the
  low-order bits, sign reinterpretation, or joining the 32-bit halves in 32-bit
  arithmetic. The interop-v2 reader algorithm's decode step points to the rule.
  Before this, the spec bound the width of the ratio product but not of
  `original_size`, and the rationale note only assumed the property.
- The rule sits in the shared `ratio-product-rule` block, so both documents carry
  the same text and
  [`tools/check-spec-duplication.py`](tools/check-spec-duplication.py) guards it.
  The rationale note now cites the rule instead of assuming it.
- [`test-vectors/interop-v2.json`](test-vectors/interop-v2.json) **1.1.0** adds
  `reject_declared_size_wraps_32_bits`: a `method 0` container whose
  `original_size` is `2³²` plus the payload length. Readers MUST reject it. A
  reader that truncates `original_size` to 32 bits sees a size that matches the
  payload and accepts it. The existing 1 TiB `reject_declared_size_bomb` cannot
  show this, because its low 32 bits are zero.
- The reference self-check in
  [`tools/interop-v2-reference.py`](tools/interop-v2-reference.py) now fails
  unless a reader that truncates only `original_size` to 32 bits accepts exactly
  that vector, and unless the vector also catches a reader that joins the halves
  as `hi | lo`.
- **No implementation change.** `cachekit-core` decodes `original_size` as `u32`
  through `rmp-serde`, which rejects an out-of-range value, whatever its marker
  width, instead of truncating it, and that conforms. No SDK vendors `interop-v2.json`, so nothing needs re-vendoring.
