### Conformance — Rust meets Encryption Activation rule 1 from cachekit-rs 0.10.0

- [`spec/intent-presets.md`](spec/intent-presets.md#sdk-conformance): the Rust cell of "Explicit
  encryption option encrypts every operation (activation rule 1)" flips ❌ → ✅ `cachekit-rs` 0.10.0+.
  Every builder encryption method and the `secure` / `secure_from_env` presets now encrypt every value
  read and write, plain `get` / `set` and `#[cachekit]` included, and with the `encryption` feature off
  the builder methods return `CachekitError::Config`. The "`secure`: L1 on, ciphertext only" Rust cell
  carries the same 0.10.0 floor: through 0.9.0 a plain `set` on the preset's client put plaintext in L1.
  Both were checked against the published 0.10.0 `.crate`.
- [`sdk-feature-matrix.md`](sdk-feature-matrix.md): the Workers feature note says what a build without
  `encryption` does from 0.10.0 (`Config`, not a silent `Ok(self)`), the Rust tamper cell covers plain
  reads on an encrypted client, and the Rust SDK summary no longer presents `SecureCache` as the only
  encrypting path. No normative text changed.
