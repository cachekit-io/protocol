### Test vectors — interop-mode.json 1.3.0 and decode-bounds.json 1.2.0 close conformance gaps (LAB-8091)

- [`test-vectors/interop-mode.json`](test-vectors/interop-mode.json) `1.3.0`. No existing vector changed.
  - **Nine key vectors.**
    - `segment_max_length`: both segments at 64 characters, the 194-character maximum key, with a
      leading digit and `-` in each segment.
    - Four map-key orders that a wrong sort gets wrong: `B` before `a` and `a-b` before `a_b`, which
      `Intl.Collator` with `caseFirst: 'upper'` reverses although it passes the three older sort
      vectors; and `ab` before `b` and U+FF61 U+FF61 before U+10000, which a length-first sort
      reverses (the second also catches a UTF-16 code-unit sort).
    - `map_key_proto`: a `__proto__` key, which a JavaScript normalizer that copies keys by assignment
      drops.
    - `set_in_map_normalized`: a tz-aware datetime and a UUID in a set in a map value, the valid twin
      of the nested naive-datetime error vector.
    - `int_beyond_float64_precision`: 2⁵³+1, −(2⁵³+1) and 2⁶³−1, and 2⁵³+1 in a list and a map value,
      which a TypeScript SDK that turns a BigInt inside int64 into a Number rounds.
    - `small_int_as_bigint`: small integers passed as `{"$int": …}`, which must take the shortest form.
  - **Two value vectors:** a `__proto__` key, and strings that start with U+FEFF (one short, one of 300
    characters), which a reader must keep.
  - **Twenty-one error vectors.** Fifteen break one segment rule in one segment, so every rule is now
    tested on both segments: over 64 characters, a leading `.`, `_` or `-`, empty, a non-ASCII digit,
    an accented or full-width letter, `/`, a space, uppercase, `:` and a trailing newline. Six put an
    out-of-model value below the top of the argument list: a naive datetime in a set in a map value,
    NaN in a map value in a list, and integers above and below the range, each in a list and in a map
    value.
  - **Two reader groups**, for an interop value reader. `reader_accept_vectors` holds six well-formed
    documents no canonical writer emits, which a reader must accept: padded integer widths, padded
    str/bin/array/map headers, unsorted map keys, a float32, an integer map key and an ext type.
    `reader_reject_vectors` holds a complete document followed by one trailing byte, with no CK frame
    prefix, so a reader that rejects only the `0x43 0x4B` prefix fails it.
  - The `tagged_json` note says a JavaScript harness wraps `$float` in a type of its own, so the SDK
    can tell an explicit float from a bare Number. The spec's Test Vectors section says so too.
- [`test-vectors/decode-bounds.json`](test-vectors/decode-bounds.json) `1.2.0` adds two reject vectors
  under a new `incomplete` reason: `incomplete_within_slot_budget` (`92 dc 00 00`) and its map twin
  `incomplete_map_within_slot_budget` (`82 de 00 00 c0`). Each is cut short, yet its declared slots fit
  the budget and every header fits the bytes after it, so only a guard that checks completeness
  rejects it before the end of the input; the map twin also passes a check that owes a pair as one item.
- `tools/interop-reference.py` and `tools/interop-crosscheck.mjs` each gain an independent value
  reader, which reads every value vector back and checks the reader groups. They also gain self-tests
  for inputs portable JSON cannot carry: a lone high or low surrogate in an argument, a map key, a
  nested value and a set; a non-string map key (Python); values outside the data model, nested too;
  and a bare JavaScript Number beyond 2⁵³. The cross-check now rejects any object that is not a plain
  object, where it used to encode a `Map` or a `Date` as an empty map; it keeps a `__proto__` key and a
  leading U+FEFF; and a naive datetime now fails in its encoder, where the nesting is, not in its
  parser. `tools/decode-bounds-reference.py` checks the new reason against its walk, and
  `tools/test_decode_bounds_reference.py` adds a mutation case for each new guard.
- [`conformance/coverage.md`](conformance/coverage.md): IOP-9, IOP-14, IOP-15, IOP-19 and IOP-20 drop
  their gaps. IOP-2, IOP-3, IOP-8, IOP-10, IOP-11, IOP-16, IOP-18, IOP-21 and IOP-29 have narrower
  ones, and IOP-13 and IOP-16 move from gap only to tests only. IOP-17, IOP-22 and IOP-35 list the new
  value and error vectors, and IOP-31 to IOP-33 the new decode-bounds vectors, so they read partial in
  every SDK until it re-vendors.
