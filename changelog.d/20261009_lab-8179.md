### Test vectors — encryption.json 1.4.0, cache-keys.json 1.2.0 and python-frame.json close encryption and cache-key conformance gaps (LAB-8179)

- [`test-vectors/encryption.json`](test-vectors/encryption.json) `1.4.0`. No existing vector changed.
  - **`master_key_first_byte_80`**, a second `master_key_input` accept row: the accept row's key with its first
    byte, `00`, replaced by `80`, with its own sealed entry (interop-mode.json's `uuid_lowercased` key holding
    `float_value_stays_float64`). A two's-complement big-integer decoder padded to 32 bytes reads every key whose
    first byte is below `80` and refuses or misreads this one. **For SDK test harnesses:** `accept_vectors` now
    holds two rows, the original first.
  - **`standard_serializer_default`** and **`standard_serializer_integrity_off`** in `vectors`: the AAD shapes
    cachekit-py's `StandardSerializer` writes, `("msgpack", True, "msgpack")` and `("msgpack", False, "msgpack")`,
    sealed over its own plaintexts (a ByteStorage envelope and plain MessagePack). With them, every AAD shape the
    current SDKs' caches write with encryption on has a sealed vector (cachekit-py's cache refuses AutoSerializer
    under encryption), so a test can decrypt what its own write path stores under the `aad_hex` of the vector with
    its shape. `tools/encryption-verify.py` freezes both shapes and checks that each plaintext is the container its
    flag claims.
  - Note wording: the block note says which row the other notes call the accept row, and that each note names
    mistakes its row catches; `raw_key_ascii_hex_string`'s note says the key it derives is other than the accept
    row's.
- [`tools/test_conformance.py`](tools/test_conformance.py): the case that checks against a base from before the
  index runs with no SDK vendoring anything, since that base predates fixture revisions SDKs vendor today.
- [`tools/encryption-verify.py`](tools/encryption-verify.py) models the padded two's-complement decoders, Python's
  and Java's, as wrong entry points that must misjudge the new row, lists `master_key_trailing_non_hex` under the
  plain `Buffer.from` model its note names, refuses two accept rows that share a master key, cache key or
  plaintext, and holds every frozen row to its position as well as its name, since consumers read
  `accept_vectors[0]`. [`tools/test_encryption_verify.py`](tools/test_encryption_verify.py) adds a mutation case for
  each guard, replaces each wrong entry point in turn with a conforming one to show its check is live, and prints
  the traceback of a case that raises.
- [`test-vectors/cache-keys.json`](test-vectors/cache-keys.json) `1.2.0`: four more derived serializer codes, `cbor`
  (→ `x23d5`, the spec's example), `toml` (→ `x0c41`, a code that starts with a zero), `<custom>:OrjsonSerializer`
  (→ `x8f72`) and `<custom>:Café` (→ `x2f62`). A derivation that maps every identity outside the table to one code,
  hashes only the `<custom>:` marker, drops the zero padding, renders uppercase hex or hashes another encoding than
  UTF-8 fails one of them. cachekit-py 0.22.0 reproduces all 21 keys.
- [`test-vectors/python-frame.json`](test-vectors/python-frame.json). No existing vector changed.
  - **Frames that pin the recorded serializer name.** `auto_serializer_write` (`s: auto`) and
    `standard_serializer_instance_write` (`s: StandardSerializer`) are cachekit-py 0.22.0 writes of the default
    value, and `std_recorded_as_given_frame` is the frame a writer that records the alias `std` as given would
    store. All three carry the default write's payload and metadata under another name, so a reader configured
    with `default` that skips the name check, or resolves the recorded name through its alias table, returns the
    value; `verify` holds them to that. `std_alias_write` and `pythonic_alias_write` write a map holding a tuple,
    which StandardSerializer and AutoSerializer write differently, so their bytes show which serializer wrote them:
    `generate` proves each equals its canonical name's write, and `verify` pins the MessagePack each holds.
  - **`integrity_checking_off_write`** (plain MessagePack, `compressed: false`) and
    **`arrow_compression_off_write`** (an `ArrowSerializer(compression=None)` instance, `compressed: false`): the
    Arrow write `spec/encryption.md` names, and a StandardSerializer write with integrity checking off. `verify`
    holds every write to the serializer name and `compressed` flag it records.
  - **Error vectors `serializer_name_missing` and `serializer_name_empty`**, rejected by a new `serializer_name`
    check: an entry that records no serializer name is a mismatch for every reader.
  - **`ciphertext_plain_msgpack_not_envelope`** and **`ciphertext_plain_msgpack_claims_uncompressed`** in
    `encrypted_read_vectors`: plain MessagePack sealed under the reader's own key and AAD where its configured
    container is a ByteStorage envelope, under a header and AAD claiming `compressed: true` and `false`. The reader
    fails closed on both; one that takes the container from the stored flag reads the second.
  - **`ciphertext_serializer_name_auto`** and **`ciphertext_serializer_name_missing`** in `encrypted_read_vectors`:
    one of the reader's own encrypted writes, which authenticates, under a header that records the serializer name
    `auto` or none. The name is no AAD input, so a reader that compares it only on plaintext entries returns the
    value; a conforming reader misses.
- [`tools/python-frame-reference.py`](tools/python-frame-reference.py) builds and proves the new vectors against
  cachekit-py (`generate`), and `verify` checks the serializer-name check, the name-check pairs, the alias writes
  and each write's recorded name and flag.
  [`tools/frame-crosscheck.mjs`](tools/frame-crosscheck.mjs) refuses a frame that records no serializer name and
  decodes a plain-MessagePack payload to its `value_json`.
- [`spec/cache-key-format.md`](spec/cache-key-format.md), [`spec/encryption.md`](spec/encryption.md) and
  [`spec/wire-format.md`](spec/wire-format.md) describe the new vectors. No normative text changed.
- [`conformance/coverage.md`](conformance/coverage.md): KEY-7 and KEY-8 drop their gaps. ENC-2 and ENC-3 move
  from gap only to vectors and a gap. ENC-5, ENC-10 and KEY-2 to KEY-6 list the new vectors with narrower gaps
  (KEY-4 and KEY-5 on encrypted entries too),
  and ENC-5's no longer says that no vector holds an `OrjsonSerializer` write. PRE-16 to PRE-18 drop the first-byte
  sentence from theirs. ENC-6, KEY-1, PRE-22, PRE-25 and PRE-28 list the new vectors. They read partial in every
  SDK until it re-vendors.
