### Feature matrix — TypeScript cache keys hash through the Rust bindings from npm 0.2.2 (LAB-11096)

- The **Blake2b-256 key generation** TypeScript cell said "via @noble/hashes". From
  `@cachekit-io/cachekit` 0.2.2, keys hash with Rust `blake2` through the NAPI binding on
  Node and the wasm binding on Workers, once a cache there first instantiates the module.
  @noble/hashes stays as the fallback and gives the same digest. Checked by running the
  published 0.2.2 and its pinned `cachekit-core-ts` 0.2.1 and `cachekit-core-wasm` 0.2.1.
- Note ¹'s Workers binding sizes were those of the first wasm build. The published
  `cachekit-core-wasm` 0.2.1 is 186,188 B (66,940 B gzipped) plus 27,654 B of JS glue,
  built with wasm-opt `-O3` and simd128, not `-Oz`.
