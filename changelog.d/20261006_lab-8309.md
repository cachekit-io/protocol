### Conformance — cachekit-rs runs `interop-mode.json` 1.3.0 and `decode-bounds.json` 1.2.0 (LAB-8309)

- `conformance/sdks.json` reads cachekit-rs at
  [`a7feb62`](https://github.com/cachekit-io/cachekit-rs/commit/a7feb62b5b589ba6126c20fa36b3f55bf02e82a2),
  the head of [cachekit-rs#152](https://github.com/cachekit-io/cachekit-rs/pull/152), which
  vendors both fixtures byte for byte and runs every vector in its default CI: the key, value
  and error vectors and both reader groups, and every decode-bounds reject vector through the
  structural guard on each read path. `conformance/coverage.md` is regenerated. For
  cachekit-rs, IOP-9, IOP-22 and IOP-35 move to `covered`. IOP-2, IOP-3, IOP-8, IOP-17,
  IOP-18, IOP-21, IOP-24, IOP-29, IOP-31 to IOP-33 and IOP-36 move to `partial (gap)`, and
  IOP-13 moves there from `uncovered`. IOP-19 and IOP-20 move from `uncovered` to
  `partial (1/2)`: cachekit-rs does not vendor `python-frame.json`.
- [IOP-17](spec/interop-mode.md#iop-17) gets a gap. Its value vectors check an SDK's value
  encoder, not the bytes its write path stores. cachekit-rs's `set`, the write path for
  interop entries, serializes with rmp-serde, not through `interop::serialize_value`, the
  encoder its vector test drives. Without the gap, this re-vendor would have read IOP-17 as
  `covered` for cachekit-rs. It reads `partial (gap)`, and will for each SDK that vendors
  1.3.0.
- The feature matrix's **Test vectors in CI** cachekit-rs cell and note ¹⁶ record both copies
  (unreleased until a cachekit-rs release carries them). The cell now dates `interop-mode.json`
  1.2.0 to cachekit-rs 0.9.0 (`.crate` inspected 2026-10-06), where it had read unreleased.
