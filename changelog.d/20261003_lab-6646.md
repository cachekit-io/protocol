### SDK feature matrix and intent presets — Rust key-input and rotation cells brought to the published cachekit-rs 0.9.0 (LAB-6646)

- Every flip below was verified against the published `cachekit-rs-0.9.0.crate` (crates.io,
  2026-10-03), not the repository branch. Python and TypeScript cells are unchanged.
- **`secure_from_env` reads the previous keys.** From 0.9.0, `CacheKit::secure_from_env(url)`
  reads `CACHEKIT_PREVIOUS_MASTER_KEYS` with the same validation as
  `CachekitConfig::from_env()`, before any Redis I/O. The
  [intent-presets](spec/intent-presets.md#sdk-conformance) companion-constructor row
  ([Explicit Configuration](spec/intent-presets.md#explicit-configuration) rule 4) is ✅ for
  Rust from 0.9.0; 0.8.0 still ignores the variable.
- **Raw-bytes master keys are exactly 32 bytes.** From 0.9.0, `encryption_from_bytes`,
  `encryption_from_bytes_with_previous`, `EncryptionLayer::new` and
  `EncryptionLayer::with_previous_keys` reject any key, current or previous, that is not
  exactly 32 bytes. The [Master Key Input](spec/intent-presets.md#master-key-input) rule 4
  clause of the hex-key conformance row is ✅ for Rust from 0.9.0. The hex path still
  accepts keys of 32 bytes or more.
- **Rotation recipe narrowed.** The [matrix](sdk-feature-matrix.md#encryption) Key rotation
  cell and note ⁵, [encryption.md](spec/encryption.md#key-rotation-keyring) and the
  [decision record](decisions/key-rotation.md) no longer say `secure_from_env` ignores the
  previous keys. The `CachekitConfig::from_env()` plus
  `encryption_from_bytes_with_previous` recipe now covers only the explicit-key
  `CacheKit::secure(url, master_key_hex)` and `secure_from_env` on 0.8.0, and note ⁵ warns
  that from 0.9.0 the recipe needs exactly 32-byte keys.
