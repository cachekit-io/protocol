### Conformance — the checker rejects footnote and link reference definitions

- **Definitions** (`tools/conformance.py`): a footnote definition, or a paragraph that opens
  with a bracketed label and a colon (`[label]: …`, which GitHub reads as a link reference
  definition), is now an error in an indexed spec file. GitHub moves a footnote to the end of
  the page, or drops it when nothing cites it, and shows no part of a definition, so a
  backtick inside either can no longer pair with one outside it and hide a keyword GitHub
  shows. No spec file uses either.
- **MUST NOT**: [conformance/README.md](conformance/README.md) now says that a line break
  inside an HTML block parts the two words, as the checker has always read it: a `<pre>`
  element keeps the line break, and the checker does not track HTML elements.
- **Exemption**: `<!-- not-a-requirement -->` must stand alone on the line before its fence,
  trailing spaces aside; a non-breaking space after it no longer exempts the fence.
- **Report**: a keyword's excerpt in [conformance/coverage.md](conformance/coverage.md) is now
  taken from the paragraph, table cell or block the checker reads it in, rather than guessed
  from the lines around it. Every current excerpt is unchanged.
