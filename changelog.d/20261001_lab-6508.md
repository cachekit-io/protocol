### Wire format — ByteStorage reject vectors (LAB-6508)

- [`test-vectors/wire-format.json`](test-vectors/wire-format.json) **1.3.0** adds
  a `reject_vectors` group: six hex-pinned canonical `bin` envelopes that readers
  MUST reject. They cover the `original_size` cap (step 4), an `original_size` of
  2³² + 16 that a reader truncating to 32 bits accepts, zero-length
  `compressed_data` and a ratio one byte past 1000:1 (step 5), a declared size one
  byte larger than the decoded output (step 6 or 9), and a checksum mismatch
  (step 8). Until now every vector in the file was an accept vector, and a reader
  with none of these checks passed all of them. The 14 hex-pinned vectors and the
  constructed vector are unchanged. Each vector's `reject_step` is where the
  reference reader rejects it; it is not a value an SDK must match.
- [`spec/wire-format.md` → Reject vectors](spec/wire-format.md#reject-vectors) is a
  new section, and it adds MUSTs for an SDK's conformance test. For each vector, the
  test asserts the error the section's table names, not merely a failed read: the
  size-cap, zero-length and ratio errors, and a length error rather than a checksum
  error for the length vector. For the size-cap and ratio vectors, the test also
  measures peak allocation during the read and fails if it reaches
  `original_size`, because a reader can reserve the output buffer first and still
  raise the expected error. The section also says why steps 1 and 3 have no vector.
  The Retrieve Flow pseudocode comment on the zero-length check no longer implies
  that an empty block with `original_size` 0 is acceptable.
- [`tools/wire-format-reference.py`](tools/wire-format-reference.py) pins the
  reject-vector set in code, derives each vector from its legacy base, and checks
  that its reader rejects each one at its `reject_step`. Its reader's rejections now
  carry the step number, and its codec reads and writes `uint64`.
- [`tools/test_wire_format_reference.py`](tools/test_wire_format_reference.py)
  drops each bound from the reference reader in turn, and truncates its
  `original_size` decode, and checks that only that bound's vectors change outcome.
  It also checks that a reader which decompresses first misses the size-cap and
  ratio errors, and that a `tracemalloc` probe catches a reader that reserves
  `original_size` before its checks.
- **For SDKs that vendor `wire-format.json`:** re-vendoring 1.3.0 changes the file's
  sha256. Loaders that read only `vectors` keep passing.
