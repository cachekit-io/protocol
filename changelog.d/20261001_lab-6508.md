### Wire format — ByteStorage reject vectors (LAB-6508)

- [`test-vectors/wire-format.json`](test-vectors/wire-format.json) **1.3.0** adds
  a `reject_vectors` group: six hex-pinned canonical `bin` envelopes that readers
  MUST reject. They cover the `original_size` cap, an `original_size` of 2³² + 16
  that a reader truncating to 32 bits accepts, zero-length `compressed_data`, a
  ratio one byte past 1000:1, a declared size one byte larger than the decoded
  output, and a checksum mismatch. Until now every vector in the file was an accept
  vector, and a reader with none of these checks passed all of them. The 14
  hex-pinned vectors and the constructed vector's bytes are unchanged. Each vector's
  `reject_step` is the Retrieve Flow step at which the reference reader rejects it,
  not a value an SDK must match.
- [`spec/wire-format.md` → Reject vectors](spec/wire-format.md#reject-vectors) is a
  new section with MUSTs for an SDK's conformance test. The test drives each vector
  through the envelope read path and asserts the error the section's table names.
  For five of the six vectors, a failed read alone does not show the bound. For the
  size-cap and ratio vectors, the test also bounds what the read allocates. It
  counts high-water or cumulative bytes requested from the envelope code's own
  allocator, and it has a positive control. The section also says why Retrieve Flow
  steps 1 and 3 have no vector. The Retrieve Flow pseudocode comment on the
  zero-length check no longer implies that an empty block with `original_size` 0 is
  acceptable.
- The reference tools (`tools/wire-format-reference.py`,
  `tools/test_wire_format_reference.py`) verify the group, and mutation-test that
  each vector isolates its bound.
- **For SDKs that vendor `wire-format.json`:** re-vendoring 1.3.0 changes the file's
  sha256. Loaders that read only `vectors` keep passing.
