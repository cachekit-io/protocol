### Conformance — wire-format and File backend requirement ids; the checker reads blocks as GitHub does

- **Requirement ids**: every MUST and MUST NOT in [wire-format.md](spec/wire-format.md)
  (`WIRE-1` to `WIRE-24`) and [file-backend-format.md](spec/file-backend-format.md)
  (`FILE-1` to `FILE-6`) now carries an id, indexed in
  [conformance/requirements.json](conformance/requirements.json) and reported per SDK in
  [conformance/coverage.md](conformance/coverage.md). No normative text changed;
  `tools/conformance.py strip` removes the ids.
- **What the new mappings show**: of the 30, 2 are fully pinned by vectors, 22 partly,
  3 only by reference-tool tests, and 3 by nothing. The envelope rules bind cachekit-py and
  cachekit-ts (cachekit-rs stores plain MessagePack), and the CK v3 frame rules bind
  cachekit-py. A reject vector's verdict rarely shows the check it was built for: a reader
  missing that check usually rejects the vector anyway, so only a test that asserts the
  named error, or the allocation bound, exercises it.
- **Checker** (`tools/conformance.py`): a spec file is now read into blocks by
  CommonMark's parsing strategy as GitHub's renderer applies it (blockquotes, list items,
  lazy continuation lines, HTML blocks, setext headings, GFM tables including one-column
  tables without pipes), so a code span pairs only inside the paragraph, heading or table
  cell a reader sees. MUST NOT is one keyword only inside one paragraph or heading: a MUST
  whose NOT starts another block, or sits past a literal `>`, needs its own id, so an id
  after that NOT no longer marks it. An HTML block is raw HTML: a keyword in it shows even
  between backticks. A keyword in an indented code block is now an error, like one in a
  fence; a tab, and an HTML block that leaves a comment open, are errors too. A closing
  fence may now sit at a different indent from its opener, as CommonMark allows. A `.mjs`
  test must be declared in code, not in a comment, string or template literal.
- **Shared spec blocks** (`tools/check-spec-duplication.py`): requirement ids are ignored
  when the two copies of a shared block are compared, since one copy's file may be
  indexed before the other's.
