### Conformance — the checker reads inline markup the way GitHub shows it

- **Inline markup** (`tools/conformance.py`): within a paragraph, heading or table cell, the
  checker now reads HTML tags, comments, autolinks and backslash escapes the way GitHub's
  renderer does, whichever opens first taking its whole extent. A backtick inside one of them
  no longer pairs with a later backtick to hide a keyword that GitHub shows, and a tag may span
  lines inside a blockquote.
- **Comments** end where GitHub shows them ending, inline and in HTML blocks: at the first `-->`
  or `--!>`, with `<!-->` a whole comment. A keyword after that needs an id.
- **Openers that close nothing**: after a run of backticks with no closer or more than 80
  backticks, or a `<!` or `<?` that is not a closed comment, the checker reads the rest of the
  paragraph or table cell as plain text. GitHub may hide part of it, so a keyword in later inline
  code there can need an id; closing or escaping the stray backtick avoids that. No spec file's
  keywords change; see [conformance/README.md](conformance/README.md).
