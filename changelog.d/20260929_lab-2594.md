### Decompression bomb bound — one ≥ 64-bit rule, guarded in both specs (LAB-2594)

- [`spec/wire-format.md`](spec/wire-format.md) § Security Limits now carries the
  same normative obligation as
  [`spec/interop-v2.md`](spec/interop-v2.md) § Security Limits — *"The ratio
  product MUST be computed **exactly**"* — in an
  identical block (modulo each document's operand name, `compressed_size` vs
  `payload.length`). Previously interop v2 bound the integer width
  ([#53](https://github.com/cachekit-io/protocol/pull/53)) and wire format said
  nothing, so an implementer reading only wire format could legally compute the
  product in 32-bit pointer-width arithmetic.
- The rule names the **operation**: widen the operand *before* multiplying, to a
  ≥ 64-bit unsigned or arbitrary-precision integer, or to an IEEE-754 binary64
  whose operand and product are exact integers. Rust `u64`, Python `int` and
  JavaScript `Number` (the product is < 2³⁹, so no `BigInt`) all conform.
- The `if max_allowed overflows: REJECT` pseudocode is **removed**, not reworded.
  It is not an observable event in Rust release builds, JavaScript or Python,
  and once the operand is widened the two 512 MiB caps bound the product below
  2³⁹, so the branch is unreachable. Rejecting on overflow is explicitly **not** a
  substitute for widening. Wire format now also states both caps as a normative
  precondition of the product bound and enforces them inline in its pseudocode.
- The bound MUST be computed by **multiplication**. Truncating integer division
  (`original_size / compressed_size > 1000`) accepts up to
  `1000·compressed_size + (compressed_size − 1)`, a looser bound than the spec
  permits.
- **`spec/interop-v2.md`'s rationale corrected**: 32-bit wrapping was said to
  corrupt the bound "in both directions". It can only *tighten* it, from a
  compressed payload of `⌈2³²/1000⌉ = 4,294,968` B (~4.29 MB) upward, so the
  failure mode is **spurious rejection**, never a bomb bypass — a hard error that
  is permanent for an affected entry. Both documents now say so, in a
  non-normative note.
- **New CI guard**: [`tools/check-spec-duplication.py`](tools/check-spec-duplication.py)
  compares the two copies of the rule, and of the pseudocode lines that compute
  and compare the product, modulo the operand rename and common indentation. A mutation suite
  ([`tools/test_check_spec_duplication.py`](tools/test_check_spec_duplication.py))
  re-arms the original divergence and asserts the guard fails.
- **No implementation change.** `cachekit-core` already computes the product in
  `u64` with `checked_mul`, correct on every target including wasm32. No limit
  values changed and no fixture bytes were touched (no SDK re-vendors).
