### SaaS API — `405`, the `PATCH /ttl` cap `400`, `ck_sdk_` examples and authentication precedence (LAB-4146)

- [`spec/saas-api.md` → HTTP Status Codes](spec/saas-api.md#http-status-codes) now lists
  `405 Method Not Allowed` with each `/v1/cache/*` route's `Allow` methods; it is evaluated
  after authentication. [Error Classification](spec/saas-api.md#error-classification) lists
  it as Permanent.
- [`PATCH /v1/cache/{key}/ttl`](spec/saas-api.md#patch-v1cachekeyttl) documents the `400`
  returned when `ttl` plus the entry's stored stale window exceeds the 30-day TTL cap. The
  client cannot pre-validate it; a `PATCH` with a smaller `ttl` can succeed.
- The `GET` and `PUT /v1/cache/{key}` sections add a `ck_sdk_` request example carrying the
  required `X-CacheKit-L1-Status` header.
- The authentication outcome — `401`, or `503` for a key-store fault — precedes every other
  error.
- Clarification only: documents existing server behaviour; no wire or SDK change.
