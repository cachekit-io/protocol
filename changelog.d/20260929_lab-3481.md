### Interop mode — SDKs vendor decode-bounds 1.1.0 and assert the structural guard (LAB-3481)

- cachekit-py ([cachekit-py#363](https://github.com/cachekit-io/cachekit-py/pull/363)),
  cachekit-rs ([cachekit-rs#93](https://github.com/cachekit-io/cachekit-rs/pull/93)) and
  cachekit-ts ([cachekit-ts#152](https://github.com/cachekit-io/cachekit-ts/pull/152))
  vendor [`test-vectors/decode-bounds.json`](test-vectors/decode-bounds.json) `1.1.0`
  byte for byte, and each conformance test asserts, for every reject vector, an error
  that only a pre-decode check produces: the structural guard's own error, or in
  cachekit-ts the invalidation-event size cap that rejects an oversize vector ahead of
  it. Where a size cap rejects first, [Decode bounds](spec/interop-mode.md#decode-bounds)
  also requires a direct call to that entry point's structural guard, which cachekit-ts
  does not yet make for its three oversize vectors.
- cachekit-rs's structural guard now enforces nesting depth itself; before, the two
  depth-only `1.1.0` vectors passed it and were rejected only mid-decode.
- [Feature matrix](sdk-feature-matrix.md#protocol-compliance) Test vectors in CI row:
  the Python and Rust decode-bounds ⚠️ for the guard-assertion gap are gone. Python
  remains ⚠️ only for the envelope entry point (see the Wire format row). TypeScript is
  ⚠️ for the envelope entry point and for the invalidation event entry point's three
  reject vectors over its 4096 B size cap.
