### Test vectors — encryption.json 1.5.0 and cache-keys.json 1.3.0 add reject, container, keyring-configuration and serializer-object tables (LAB-8179)

- [`test-vectors/encryption.json`](test-vectors/encryption.json) `1.5.0` adds three tables. No existing vector
  changed.
  - **`aad_reject_vectors`**: six published ciphertexts presented under AAD inputs that differ from the ones they were
    sealed under in one component (the other `compressed` value either way, `msgpack` for `arrow`, `original_type`
    dropped and added, and the cache key with a prefix in front). Each row has a vector's fields plus `sealed_as`
    and `note`, so a harness can run its decrypt path on it and assert that authentication fails. A reader that
    retries with another AAD input decrypts it.
  - **`decrypted_container`**: six plaintexts sealed under the AAD of the reader each names in `reader`
    (`plain_msgpack`, `bytestorage_envelope`, `arrow_checksummed` or `orjson_checksummed`), in a container that
    reader is not configured for or must not unwrap, with the `outcome` a conforming read gives (`document` or
    `error`). A reader that sniffs the plaintext, falls back to another container, or ignores bytes after the
    first document or envelope returns a value from one of them.
  - **`keyring.configuration`**: four configurations a keyring is loaded from, with the `verdict` a conforming SDK
    gives at load: three decrypt-only keys (accept), four (reject), and the current key repeated in the decrypt-only
    list as given and in uppercase (reject either way, whatever an SDK does with uppercase hex).
- [`tools/encryption-verify.py`](tools/encryption-verify.py) verifies each table, models each mistake a note names
  as a wrong reader or loader that must misjudge its row, and refuses a row whose verdict turns on something the
  spec leaves open. [`tools/test_encryption_verify.py`](tools/test_encryption_verify.py) adds a mutation case for
  each guard.
- [`test-vectors/cache-keys.json`](test-vectors/cache-keys.json) `1.3.0` adds two tables. No existing vector changed.
  - **`error_vectors`**: an empty, a `null` and an integer serializer identity, which key generation must refuse
    with an error.
  - **`serializer_object_vectors`**: the serializer as a class a test instantiates and configures a cache with
    (`serializer_class`, and `defined_by`: the SDK's own class or one the test defines). cachekit-py's
    `ArrowSerializer` keys as `x2263`, and a class named `auto` as `xf932`, never AutoSerializer's `a`.
  cachekit-py 0.22.0 passes every row.
- [`spec/encryption.md`](spec/encryption.md) and [`spec/cache-key-format.md`](spec/cache-key-format.md) describe the
  new tables. No normative text changed.
- [`conformance/coverage.md`](conformance/coverage.md): ENC-3, KEY-2, KEY-6 and KEY-9 drop their gaps. ENC-1, ENC-7,
  ENC-9 and KEY-10 move from gap only to vectors and a gap, and ENC-2 lists the container rows with a narrower gap.
  They read partial in every SDK until it re-vendors.
