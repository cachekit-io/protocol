### Feature matrix — SaaS API deviations in each SDK's CachekitIO client (LAB-8206)

- The **Compliance Status** table's SaaS API row no longer marks any SDK fully compliant.
  Each cell names its deviations from [spec/saas-api.md](spec/saas-api.md), checked against
  the published artifact on 2026-10-05:
  - Python, through `cachekit` 0.22.0: a PUT also sends the legacy `X-TTL`
    ([API-44](spec/saas-api.md#api-44)); a fractional TTL, stale window or `refresh_ttl`
    value goes out unrounded, so a sub-second one is rejected with `400`
    ([API-42](spec/saas-api.md#api-42), [API-54](spec/saas-api.md#api-54)); `ttl=0` is sent
    rather than rejected. The first two are fixed in
    [cachekit-py#520](https://github.com/cachekit-io/cachekit-py/pull/520), open.
  - Rust, through `cachekit-rs` 0.10.0: `refresh_ttl` rejects a sub-second TTL instead of
    sending 1 ([API-42](spec/saas-api.md#api-42)). Fixed in
    [cachekit-rs#142](https://github.com/cachekit-io/cachekit-rs/pull/142), open.
  - TypeScript, through npm 0.1.5: a PUT sends only `X-TTL`, unrounded, and stores `ttl` 0
    with no expiry (fixed on `main` by
    [cachekit-ts#110](https://github.com/cachekit-io/cachekit-ts/pull/110), unreleased); and
    a `200` lock response with an absent, empty or non-string `lock_id` counts as a lease
    ([API-65](spec/saas-api.md#api-65)), fixed in
    [cachekit-ts#215](https://github.com/cachekit-io/cachekit-ts/pull/215), open.
- The **Stale-while-revalidate (server stale-grace)** row marks Python ✅ from PyPI 0.14.0,
  the first published release that writes `X-CacheKit-Stale-TTL` and revalidates a stale
  read, in place of 🚧.
