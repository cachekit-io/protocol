### Conformance — links, footnote references, bare addresses and NUL bytes

- **Links** (`tools/conformance.py`): a link title, or a backtick, `<`, backslash, parenthesis
  or quote in an inline link's destination, is an error. GitHub takes the destination and title
  whole, so a backtick there opens no code span; the checker paired it with a later backtick and
  hid a keyword GitHub shows. Percent-encode the character. Backticks in link text are read as
  before.
- **Footnote references**: `[^…]`, and a `[` before an escaped `^` or any `&`, are errors.
  Footnote definitions already were, so no reference resolves, and GitHub shows an unresolved
  one as its raw text, inline code included.
- **Bare addresses**: a backtick or backslash in a GFM extended autolink (a bare `www.`,
  `http://`, `https://` or `ftp://` address, in any case) is an error. GitHub links it up to the
  next space or `<`, so a backtick in it opens no code span and a backslash at its end escapes
  nothing.
- **NUL bytes** in a spec file are an error, like a tab. No spec file's keywords change; see
  [conformance/README.md](conformance/README.md).
